# Trio64V+ ROM (765): fixes and improvements

What 1.03-08-pN (the level in [`src/tools/common/version.inc`](../src/tools/common/version.inc)) changes against S3's Trio64V+ BIOS 1.03-08, each
with the issue that has the details. Most p1 changes are backports from the Trio64V2 ROM
([`docs/775-changes.md`](775-changes.md)): the issue is the Trio64V2 one, which carries the label 765. p2 fixes
faults of 1.03-08 itself. The build, what does not apply to the Trio64V+ and why, the per-call costs and
the card runs are in [`docs/765-rom.md`](765-rom.md).

| Change | Level | Issue | How |
| --- | --- | --- | --- |
| 32-bit video memory stores: S3/VESA mode set clear, VGA mode set clear, font load into plane 2, mode 13h scroll, text scrolls (full width, window moves and blank fills), planar scrolls, AH=09h text | p1 | [#60](https://github.com/perchrh/trio64-vbios-tools/issues/60), [#61](https://github.com/perchrh/trio64-vbios-tools/issues/61), [#62](https://github.com/perchrh/trio64-vbios-tools/issues/62), [#51](https://github.com/perchrh/trio64-vbios-tools/issues/51) | Every routine these patches replace is in 1.03-08 byte for byte: `s3vpatch.py` checks the same signatures as `s3patch.py`, at other addresses, and assembles the same files (`clear32.asm`, `p13*.asm`) with the 1.03-08 addresses of [`src/roms/vplus/bios.inc`](../src/roms/vplus/bios.inc). wmove and bfilla use the dead bytes after the clear and font load jumps, as in 2.04.07; the rest is in the free block 7AE0h-7D2Dh. |
| Booster: the 64 KB linear window at A0000h in banked packed modes | p1 | [#47](https://github.com/perchrh/trio64-vbios-tools/issues/47) | On at the end of a banked 4F02 and at the first bank switch (4F05 or the window function), as 2.04.07-p18 (`vhooks.asm`). The real base needs no save: 1.03-08 keeps the PCI base (bits 31-24) in CR6B from POST and writes it back to CR59 (CR5A = 00h) at every mode set (1015h); the mode set hook does it too, before the mode set. |
| Windows enhanced mode check | p1 | [#47](https://github.com/perchrh/trio64-vbios-tools/issues/47) | As 2.04.07-p17: no booster while INT 2Fh AX=1600h reports Windows in enhanced mode, asked once per mode set (CR6D = 01h marks the refusal; 1.03-08 does not use CR6D). |
| Fast 4F05h set window | p1 | [#59](https://github.com/perchrh/trio64-vbios-tools/issues/59) | At the INT 10h entry (`vext.asm`): 6 port writes where 1.03-08 needs 10 (the dispatcher unlocks CR38/CR39 twice and saves, sets and restores SR08). 1.03-08 neither keeps the bank at 0040:04FE nor refuses 4F05 with linear addressing on, so neither does the fast path. |
| Attribute controller flip-flop reset after the mode set | p1 | [#52](https://github.com/perchrh/trio64-vbios-tools/issues/52) | In the mode set hook, for AH=00 and 4F02. |
| The 32 KB twice in a 64 KB image, for boards that map either half of a 64 KB EEPROM; the default since 2 November 2026 (`SIZE765=32` for a 32 KB EEPROM) | p1 | [#78](https://github.com/perchrh/trio64-vbios-tools/issues/78) | `s3vpatch.py`, `--size 32` for the 32 KB alone; the PCI ROM header declares one 32 KB image. |
| MCLK build option (`MCLK=`, `MEMTYPE=edo1, fpm`) | p1 | [#112](https://github.com/perchrh/trio64-vbios-tools/issues/112) | Sets one entry of the MCLK table, at most 60 MHz (MEM-1); README "MCLK build option". |
| 4F02 refuses a mode that does not fit the video memory | p2 | [#107](https://github.com/perchrh/trio64-vbios-tools/issues/107) | After the mode lookup (4924h), 4F01's own rule (C000:4898): BytesPerScanLine x YResolution, x 4 in 16 colours, in 64 KB units, must be below the memory size from CR36. Otherwise AX = 014Fh and nothing changes, as for an unknown mode. 1.03-08 set them: with 2 MB 118h, 119h, 11Ah, with 1 MB also 107h, 112h, 115h-117h, 120h. |
| The VBE functions keep the 32-bit registers | p2 | [#108](https://github.com/perchrh/trio64-vbios-tools/issues/108) | The dispatcher (47CDh) calls each function between PUSHAD and POPAD; the functions return through the INT 10h frame, so no result changes. 1.03-08 handed back EAX, ECX and EDX with changed upper halves after 4F06. |
| No interlaced timing | p2 | [#68](https://github.com/perchrh/trio64-vbios-tools/issues/68) | 118h (1024x768x16M), 119h/11Ah (1280x1024x32K/64K) and 120h (1600x1200) exist only interlaced on the Trio64V+ (CLK-1: 50 MHz at 32 bpp, 80 MHz at 15/16 bpp, 135 MHz clock-doubled 8 bpp; their 60 Hz timings need 65, 108 and 162 MHz). They leave the mode table (0128h, S3 modes 78h-7Ch) and the VESA list (4C13h with 4C51h); the S3 numbers 207h-213h move up behind the first FFFFh. The interlaced last entries of the 1024x768 and 1280x1024 refresh lists (055Ah, 0587h, 0605h, 0656h) are cut off by an end mark on the entry above, so refresh index 0 gives the lowest non-interlaced rate. As in the Trio64 ROM. |
| 10Dh-10Fh with the DCLK VCO in range | p2 | [#113](https://github.com/perchrh/trio64-vbios-tools/issues/113) | The DCLK at 25.06 MHz (VCO 200.5 MHz) in place of 12.62 MHz (VCO 101 MHz), halved after the mode set; [`docs/765-rom.md`](765-rom.md), "10Dh-10Fh". Halved by SR01 bit 3 at p2-p7: the picture checked on the STB card at p7 (11 November 2026, [#238](https://github.com/perchrh/trio64-vbios-tools/issues/238)): 10Dh fine, 10Eh and 10Fh wrong, [#247](https://github.com/perchrh/trio64-vbios-tools/issues/247); halved by SR15 bit 4 since p8. |
| Interrupts off in the sequencer reset of 10Dh-10Fh (`msx`) | p3 | [#116](https://github.com/perchrh/trio64-vbios-tools/issues/116) | `cli` from reading the sequencer index to putting it back; the popf at the end of `msx` restores IF. |
| Base S3's 1.03-08N (theretroweb) in place of 1.03-08 (GW503A dump): 1-cycle EDO MCLK 50.11 MHz, no monitor sense at POST; sign-on 1.03-08N-pN | p4 | [#129](https://github.com/perchrh/trio64-vbios-tools/issues/129) | The same code; the configuration bytes differ ([`docs/765-rom.md`](765-rom.md), "The reference image"). `s3vpatch.py` takes only 1.03-08N. |
| MCLK 50.11 MHz in both entries by default: the fast page and 2-cycle EDO entry A6h lowered from 59.96 MHz to the 1-cycle EDO clock (owner's decision, 7 November 2026; `MCLK=60 MEMTYPE=fpm` builds the old value) | p6 | none (not a fault) | `s3vpatch.py` `DEFAULT_MCLK`; README "MCLK build option". |
| Fast 4F05 set window picks the CRTC port with GETCRTC (MISC bit 0) instead of a hardcoded 3D4h, so it also works in the mono modes (3B4h), where 3D4h writes are not decoded | p7 | [#217](https://github.com/perchrh/trio64-vbios-tools/issues/217) (the #193 class on the Trio64V2) | `vext.asm` `int10x`: `call GETCRTC` for the CR38/CR39 unlock, the CR58 read and the CR6A write, the port kept across the sequencer access (`push dx`/`pop dx`); no extra port writes. Emulator: `mono_4f05` on the 765 model XPASSes, S3COMPAT's Mode 07h/0Fh lines of #215 no longer FAIL 80; `make 765-rom-test` pins the new SHA-256. |
| 10Dh-10Fh halved by SR15 bit 4, not SR01 bit 3, and at 60 Hz | p8 | [#247](https://github.com/perchrh/trio64-vbios-tools/issues/247) | `vfix.asm` `msx` sets SR15 bit 4 (DCLK / 2 into VCLK, the RAMDAC clock; CLK-5) instead of SR01 bit 3 (the character clock only, which the 16/32 bpp pixel path did not follow on the STB card at p7), and the CRTC tables 02B8h/0693h get a 525-line frame (CR06 = 0Bh, CR07 = 3Eh) instead of 449: 31.3 kHz, 59.7 Hz instead of 31.5 kHz, 69.8 Hz - the 60 Hz class LCDs commonly take, as no standard 320x200 mode is other than 70 Hz and the 70 Hz needs the 12.6 MHz pixel clock the Trio64V+ cannot make within the VCO range (owner's decision). The stock Phoenix BIOS of the STB card halves these modes with SR15 bit 4 and displays them correctly (results/86C765-stock-stb.ZIP, kept local). DCLK stays 25.06 MHz (VCO 200.5 MHz, the p2 pair). Emulator: `765_patches` checks VCO in range, SR15 bit 4 set, SR01 bit 3 clear, 525 lines, 59.7 Hz at 31.3 kHz; S3TEST's vmodelist lists the three modes at 59.7 Hz; `make 765-rom-test` pins the new SHA-256. The picture on a card is still to be checked (VBESHOW without /R on 10Dh-10Fh). [`docs/765-rom.md`](765-rom.md), "10Dh-10Fh". |
| Fonts built from public domain sources (the same bytes) | p5 | [#141](https://github.com/perchrh/trio64-vbios-tools/issues/141) | `s3vpatch.py` writes all five tables (8x8, 8x14, 9x14 and 9x16 alternates, 8x16) from [`src/roms/fonts`](../src/roms/fonts/), built from Joseph Gil's public domain font collection; byte for byte the tables 1.03-08N carries, so nothing on the screen changes. |

Not carried, and why (details in [`docs/765-rom.md`](765-rom.md), "Does not apply to the Trio64V+"): the FIFO fetch fix
([#53](https://github.com/perchrh/trio64-vbios-tools/issues/53)), CR23 before CR26 ([#50](https://github.com/perchrh/trio64-vbios-tools/issues/50)), the POST delay ([#48](https://github.com/perchrh/trio64-vbios-tools/issues/48)) and the DDC fixes ([#49](https://github.com/perchrh/trio64-vbios-tools/issues/49), [#86](https://github.com/perchrh/trio64-vbios-tools/issues/86)), which concern Trio64V2
registers or 2.04.07 code; the LFB fixes of the booster and 4F06 BL=3 ([#55](https://github.com/perchrh/trio64-vbios-tools/issues/55)), VBE 2.0 functions; the
black level ([#63](https://github.com/perchrh/trio64-vbios-tools/issues/63)), a Trio64V2 register; 1600x1200 at 60 Hz, beyond the chip's clock.
