## Verdict

A clean ROM is feasible for one known board: the ExpertColor DSP-3364P, 86C764X, 2 MB fast page memory. The current package is not ready to implement from.

The recommended order:
1. Correct the specifications and the acceptance tests.
2. Prove a conservative mode 03h cold boot on the card.
3. Only then widen compatibility.

The reviewer's own runs:
- The three default ROM builds match their pinned SHA-256.
- The three patcher suites pass.
- The 2 MB emulator suites show 64 PASS, 17 deliberate SKIP and no unexpected failure, under the project's current allowances.

## Known limitations it lists (not new defects), and where they stand

- **Cold initialisation is not modelled faithfully.**
  - What the model lacks: CR36 forced, no lock enforcement, PCI device addressing, no memory aliasing, PLL settling or refresh.
  - The POST spec names most of this.
  - A 1/2/4 MB emulator matrix does not prove memory sizing.
- **Code coverage is not hardware coverage.**
- **Input identity.** s3patch and s3vpatch accepted a changed code byte outside their patch sites; s3tpatch's CODE_SHA did not. Fixed (#143): both now check CODE_SHA over 0100h-7FFDh.
- **Release terms.** No grant is recorded yet for our original code, tests and specs, and no asset manifest: #145. The owner chose the MIT licence on 2 November 2026; the licence file and the manifest are still to be added.
- **Fonts.** Since #141, all three ROMs build their fonts from Joseph Gil's public domain files ([`rompatch/fonts/`](../../rompatch/fonts/)). The bytes equal S3's and IBM's VGA font, so the origin question for a distributed clean ROM stays with the lawyer ([`docs/clean-room.md`](../clean-room.md)).
- **Isolation.** The clean handoff is not isolated yet: export a reviewed allowlist at a fixed commit to a separate repository (#145).
- **Distribution policy.** Reference ROMs are tracked and patched images are uploaded as a CI artifact (#145). Since 2 November 2026 no workflow uploads a patched image; the reference ROMs stay until they are fetched from theretroweb (README "To do").
- **Toolchain versions.** Record the exact Python, Unicorn and Capstone versions with each qualification run.

## New sources it names

- **The DSP-3364P's DRAM:** the Mosel Vitelic V53C16256H data sheet, preliminary Rev. 2.3, December 1997.
  - Refresh: 512 cycles in 8 ms (page 1 and page 6, AC parameter 52).
  - Power-up: a 200 us pause, then at least eight RAS cycles (page 16): part A's POST-41 since 2 November 2026 (#145).
  - Not yet in [`datasheets/`](../../datasheets/).
- **PCI 2.3 section 6.3:** the option ROM header, PCIR, INIT, shadowing and the device address. Part A cites it as the source of its option ROM rules since 2 November 2026 (#145).
