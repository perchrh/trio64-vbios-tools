# Owner decisions that close independent-review returns (milestones 1-4)

Recorded 5 November 2026 to answer returns the independent leak review of 2 November 2026 would not
invent ([#145](https://github.com/perchrh/trio64-vbios-tools/issues/145),
[`README.md`](README.md) "Authorized independent review - 2026-11-02"). Dirty side only until the
changed specification rows pass a fresh leak review. Not legal advice.

These follow from the already decided milestone scope (DSP-3364P; POST; MS-DOS/EDIT; Superscape;
Chris's 3D Benchmark with VESA **101h** only).

| ID | Decision | Spec effect |
| --- | --- | --- |
| Q100 | Mode **100h** is queryable: 4F01h returns its public 640x400x8 geometry and window fields. It is **not** settable in milestones 1-4: ModeAttributes bit D0 clear (not supported in this configuration), and 4F02h BX=0100h returns the unsupported-mode failure status of part C. It may appear in the 4F00h list only if the list is allowed to name unsupported modes that 4F01h reports with D0 clear; otherwise omit it from the list and still answer 4F01h. Prefer: **list 101h then FFFFh** for the milestone-4 clean copy; still succeed 4F01h for CX=0100h with D0 clear so Chris's queries get AX=004Fh without a false "settable" claim. | VBE-10/-11/-12 and mode table; milestone contract |
| Q0F | After 4F02h of 101h, AH=0Fh returns AL = **40h** (0040:0049h holds 40h). INT 10h AH=00h with AL = 40h sets the same banked 101h mode again, and AL bit 7 keeps memory as in a normal mode set. 40h is this ROM's number: it sits in 20h-7Eh, it is not S3's 69h, and it is not one of 20h, 60h or 7Fh, which the unsupported-mode test already uses. Milestone 4 does not show that the benchmark reads AL. Assigned 6 November 2026. | VBE-45; milestone contract |
| MCLK / T64-MEM-7 | **Board/project policy**, not a public chip rating. Data book MEM-1 remains 60 MHz. Default clean build for the DSP-3364P: 50.11 MHz (SR10 = 41h, SR11 = 28h; owner's decision of 7 November 2026, replacing 59.96 MHz). Optional build clocks up to 70 MHz are an explicit board overclock policy (observed 69.8 MHz on that card); they must not be worded as an 86C764X datasheet rating. | POST-22/-23; T64-MEM-7 |
| FIFO / MODE-136 | For mode 101h, M = **31** (CR54 = F8h) and CR60 = FFh. The data book gives a 16-position FIFO and a worst wait of 9 + 2*M MCLKs (one slow entry cycle, then M page cycles). At 25.175 MHz and the default 50.11 MHz that wait drains about 36 bytes at M = 31 (30 bytes at 59.96 MHz), inside both the 128-byte FIFO (2 MB and 4 MB) and the 64-byte FIFO (1 MB). M = 31 is the 5-bit maximum. The old (t - 23) / 6 formula stays out of the clean copy. If a build's MCLK is low enough that the same wait would drain more than the FIFO, lower M until it fits. Assigned 6 November 2026. | MODE-136; MODE-148 |
| POST-41 | Cite [`primary-extracts/v53c16256h-power-up-and-refresh.md`](primary-extracts/v53c16256h-power-up-and-refresh.md): **200 ms** pause, then at least eight RAS-containing initialization cycles. Do not prescribe "eight CPU reads". State that initialization accesses are not memory-test results; name how the Trio64 produces RAS cycles when the sequence is chosen. | POST-41 |
| ROM-8 | Project naming policy: own identification string and version suffix; no prescribed "Version " text or first-256-byte placement from a reference BIOS. | ROM-8 |
| ROM-9 | No "IBM" bytes at offset 1Eh until a public expansion-ROM or demonstrated client need is shown. | ROM-9 |
| CONV-3/-12 | Cut from the milestone-1-4 clean copy (Windows driver acceptance is out of scope). | CONV-3, CONV-12 |
| Index/lock | Keep CONV-8/-9 as **project-chosen** contracts (AGENTS), not data-book guarantees; attribute-controller behaviour stays with B00-9 / B10-4. | CONV-8, CONV-9 |
| ID-INF | Identification facts taken from S3 driver INFs and drivers (`S3TRIO.INF`, `S3_2.DRV`, the Trio3D INFs) are **dirty-side only**: the clean implementer needs none of them to implement a BIOS; that is information the driver side requires, and the ROM does not tell chips apart by CR2F variant. Cut T64-ID-2, AV-ID-1, T3D-ID-1 and T3D2X-ID-1 from the crossing copy of [`docs/chip-rules.md`](../chip-rules.md); cut the S3TRIO.INF revision list from VP-ID-1 and the INF sentence from V2-ID-1 (the data-book and card-record parts stay); POST-6 keeps only that the two Trio64 parts give the same PCI ID and revision. Decided 8 November 2026. | POST-6; chip-rules T64-ID-2, AV-ID-1, VP-ID-1, V2-ID-1, T3D-ID-1, T3D2X-ID-1 |
| Fonts | **Closed.** Use Joseph Gil's FNTCOL16 individual fonts (public domain under his notice) and generate the five ROM tables from them at build time, including the 9-dot alternates. Gil's notice is the project licence basis; no BIOS- or other-project-sourced font bytes. FreeDOS cpidos is not the project alternative. Manifest: [`asset-manifest.md`](asset-manifest.md). Already implemented (#141). | clean-room fonts; allowlist export |
| M2-BOOT | Milestone 2 acceptance boots MS-DOS 6.22 **without** `CONFIG.SYS` and **without** `AUTOEXEC.BAT`, and with an **empty PATH**. The contract is EDIT's recorded INT 10h calls only ([`milestone-calls.md`](milestone-calls.md)). Shell helpers (CLS, DOSKEY, and other AUTOEXEC/PATH programs) are out of scope: no ownership work and no surround call table in the clean contract. | milestone 2; milestone-calls |
| M-SENSE | Milestones 1-4 do not support monochrome output, and POST performs no monitor sense: the data book's SENSE mechanism (the RAMDAC analog comparators drive the internal SENSE signal active low when any AR, AG or AB output exceeds 330 mV +/- 20%, read at STATUS_0 (3C2h) bit 4; T32/64 8.4) is not used. POST always behaves as on a colour monitor: power-on mode 03h, 0040:0089h bit 2 (monochrome display) = 0 and bit 1 (grey summing) = 0, 0040:0087h bit 1 (mono monitor) = 0. Software can still turn grey summing on for its own mode sets (B00-12). The monitor sense itself is milestone 5 ([`../clean-room.md`](../clean-room.md) "Decisions of 2 November 2026", the milestone list, item 5); its sources are extracted: the S3 sense procedure at [`primary-extracts/vision964-sense-input-utilization.md`](primary-extracts/vision964-sense-input-utilization.md), the IBM power-on mode by display type and monochrome state at [`primary-extracts/ibm-bios-power-on-mode-and-mono-state.md`](primary-extracts/ibm-bios-power-on-mode-and-mono-state.md). Decided 8 November 2026. | POST-42; clean-room milestone list |
