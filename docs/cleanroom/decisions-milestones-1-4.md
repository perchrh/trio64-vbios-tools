| Q100 | Mode **100h** is queryable: 4F01h returns its public 640x400x8 geometry and window fields. It is **not** settable in milestones 1-4: ModeAttributes bit D0 clear (not supported in this configuration), and 4F02h BX=0100h returns the unsupported-mode failure status of part C. | Q0F | After 4F02h of 101h, AH=0Fh returns AL = **40h** (0040:0049h holds 40h). INT 10h AH=00h with AL = 40h sets the same banked 101h mode again, and AL bit 7 keeps memory as in a normal mode set. 40h is this ROM's number: it sits in 20h-7Eh, it is not S3's 69h, and it is not one of 20h, 60h or 7Fh, which the unsupported-mode test already uses. Milestone 4 does not show that the benchmark reads AL. Assigned 6 November 2026. | VBE-45; milestone contract |

| FIFO / MODE-136 | For mode 101h, M = **31** (CR54 = F8h) and CR60 = FFh. The data book gives a 16-position FIFO and a worst wait of 9 + 2*M MCLKs (one slow entry cycle, then M page cycles). M = 31 is the 5-bit maximum. The old (t - 23) / 6 formula stays out of the clean copy. If a build's MCLK is low enough that the same wait would drain more than the FIFO, lower M until it fits. Assigned 6 November 2026. | MODE-136; MODE-148 |

## Decisions of 8 November 2026 closing the second-pass returns (G2)

Each answers a returned question of the second-pass review of 7 November 2026
([`README.md`](README.md) "Independent second-pass review - 2026-11-07"). The corresponding
specification rows still need the crossing-copy rewrites and a fresh leak review.

| ID | Decision | Spec effect |
| --- | --- | --- |
| A-1 | POST-41's qualifying condition is a **behavioral requirement**: before the first write whose result is relied on (and before POST-16's first pattern), the ROM performs at least eight ordinary video-memory accesses through the aperture (any mix of reads and writes); the Trio64 generates a RAS clock on each such memory cycle (T32/64 memory-cycle description, section 7). After any period without clocks longer than the fitted DRAM's refresh interval, eight accesses are performed again before video memory is relied on. The rule states this as the project's chosen qualifying sequence with its public attribution; it does not claim that arbitrary aperture reads are proved sufficient by the DRAM sheet alone. | POST-41 |
| A-5b | If no memory candidate holds, POST writes the **1 MB code and continues**: an explicit **project fallback**, not a verified-capacity claim. Mode 03h text needs 256 KB, so POST still has usable memory; VBE 4F00 TotalMemory then reports what the fallback encoded, and the rule says so. | POST-15 |
| B-1 | MODE-136's M = 31 is an **owner-selected provisional value**, not a proved safe bound. The data book's 9 + 2*M MCLK expression is an example that ends when memory access returns for FIFO filling; it does not bound arbitrary CPU/graphics traffic, page changes or refill latency, and the rule no longer claims it does. The fit arithmetic (36 bytes at 50.11 MHz into the 64-byte 1 MB FIFO) is kept as the motivation for the choice, labelled provisional. The card acceptance check (no underrun in 101h on the DSP-3364P) is **not passed yet** and must not be represented as passed. | MODE-136; MODE-103; MODE-148; MQ-11/MQ-12 |
| B-3 / Q8 | The VGA modes keep **IBM's default refresh**: CR3A bit 2 = 0 and CR11 bit 6 = 0, giving 3 refresh cycles per line. Public (IBM's default), and sufficient: 3 x 31.5 kHz = 94,500 cycles/s against the fitted DRAM's 512 per 8 ms (64,000/s). MODE-147 names the fields and this arithmetic; retention on the card stays an acceptance check, separate from the rule. | MODE-147; spec-a question 8; MQ-5 |
| B-4 | MODE-133's "as in IBM's mode 13h" equivalence claim is replaced by a **complete functional derivation** from allowlisted public sources (the IBM PS/2 and PC BIOS Interface Technical Reference of April 1987 — allowlisted 8 November 2026, DMT, Ferraro, and the T32/64 register descriptions). The identity palette (AR00-AR0F = 00h-0Fh) and the black overscan (AR11 = 00h) are **explicitly attributed project defaults**. Any exact equality with IBM's mode 13h is a derived result, not a source: the rule does not claim the IBM table as its provenance, and the 22-byte reference-ROM match is not used as evidence. | MODE-133 |
| R1 | B00-5's fill/extent exhibit: search Ferraro (readable, Internet Archive) for the exact public exhibit and cite the specific section; if no exact exhibit exists, reduce the rule to the clearly documented classes and leave the extent open.
